# 독식·금수저 정식 레인 후속 작업 요청

## 사용자 방향

독식 v2는 기존 1–10화를 편입·검토하고 11화부터 이어 간다. 독식과 금수저 두 작품 모두 스토리야드 검토 대상으로 올리고 후속 계획을 함께 남긴다. 금수저는 현재 확인된 원고가 v1 1–6화이며 7–10화는 없다.

## 독식 v2

1. 현재 10화의 사건, 인물명, 시간, 금액, 미회수 기대를 검토해 편입 기준본을 확정한다. 새로운 도입을 처음부터 생성하지 않는다.
2. 현재 기획서의 장기 도착점과 10화 이후 목표를 검토한다. 총분량을 정하고, 기존 1–10화의 사건 구간을 실행 A레일·B레일·Arc에 명시적으로 대응시킨다.
3. 장현수의 해외법인 지급보증 요청을 이어받아 11–13화의 가까운 Arc를 설계한다. 실제 거래 구조·상대 목적·시우의 행동·저항·취득할 결과를 정한다. 서류 확인만 길게 이어지는 전개로 만들지 않는다.
4. 확정한 기획·설정·출처로 InkOS 기획 입장 검사를 통과시킨다. 기존 원고 반입이 foundation을 다시 생성하고 활성 Arc 끝에서 멈출 수 있으므로 보존·대조와 구간별 처리 경로를 먼저 확인한다.
5. 1–10화 본문과 회차 상태의 실제 저장·재독해를 확인한 뒤 11화부터 집필한다. 편입 중 원고를 조용히 재작성하거나 분석 결과를 검토된 사실로 자동 승격하지 않는다.

## 금수저 v1

1. 1–6화를 보존한 채 수정할 문장과 유지할 사건을 정한다. 이야기 밖 작업 문장, 반복 비유와 반복 장면을 우선 제거 대상으로 표시한다.
2. 첫 거래의 종목·통화·원금·회수액, 신탁 잔액, 오태선의 소속·보수, 파운드 배정·레버리지·유지 비용·청산 조건을 정한다. 본문에 없는 수치를 계산 편의로 발명하지 않는다.
3. 수정본이 실제 보상을 장면으로 지급하는지 확인한다. 첫 성공 뒤 주인공이 갖는 물건·장소·생활과 본가가 보이는 실제 반응을 정한다.
4. 장기 도착점과 실행 레일·Arc를 구성한다. 현 원고의 연속성을 살릴 경우 다음 원고는 7화이며 파운드 수익은 아직 지급되지 않았다는 상태에서 시작한다.
5. 수정·검토한 기준본을 고른 뒤 InkOS 편입과 이어쓰기로 진행한다. 독식의 10화 유지 결정을 이 작품에 자동으로 복사하지 않는다.

## 공통 전달 조건과 구현 확인 사항

- Storyyard는 기획·원고를 읽고 의견을 남기는 비공개 검토면이다. InkOS가 Book·실행 레일·Arc·회차 상태를 소유한다.
- 현행 `pitch import-plan`은 일일 canary의 출처를 `v3_ff_foundry`로 기록한다. 이 대화의 Codex 원고를 그대로 넣어 출처를 잘못 바꾸지 않는다. 수동 원고의 명시 출처를 보존하는 입력 경로를 선택하거나 어댑터를 보완해야 한다.
- `import chapters`는 단순 파일 복사가 아니다. 설정 생성, 회차별 분석과 상태 저장을 수행한다. planning handoff에서 받은 기초 설정과의 대조·보존을 확인하고, 구간별 Arc 끝에서 멈추는 조건을 처리한다.
- 기존 Foundry 정본 프로젝트용 `foundry-sync`를 새 Codex 초고의 업로드 경로로 가장하지 않는다. 실제 적용 레인의 정본 투영과 현재 검토 건의 등록은 구분한다.
- 필요한 실행 산출물은 source binding, 9절 기획서, StoryRailPlan, 첫/다음 ArcPacket, story_bible·volume_outline·character_matrix·book_rules·current_state·pending_hooks, 실제 검토·선택·승인 기록이다. 텍스트 표가 있다는 이유로 실행 스키마를 통과했다고 표시하지 않는다.

## 완료를 확인할 결과

현재 단계는 두 작품의 정확한 버전·전체 원고·기획·구간·이 요청서가 스토리야드 검토 건에서 읽히는 것이다. 다음 단계는 작품별 보완안과 실행 입력을 준비하고, 원고 편입의 실제 결과를 검증하는 것이다. 현재 요청만으로 미정 후속 사건이나 사람의 품질 판정을 만들어 기록하지 않는다.
