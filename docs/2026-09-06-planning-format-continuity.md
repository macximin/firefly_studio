# 전체 기획서와 초반 변주 연결 복구

2026-09-06

후속 정정: 아래의 ‘기존 9절을 먼저 표시’ 결정은 폐기했다. 제외한 시계 사건이 현재안처럼 보이는 문제를 일으켰다. 현재 변주를 먼저 표시하고 기존 문서를 접힌 과거 참고로 유지하도록 수정했다. [현재안 표시 정정](2026-09-06-current-plan-visibility-fix.md)을 우선한다.

사용자가 초반 변주 화면에서 기존 기획서와 육하원칙이 사라진 문제를 지적했고, 연결 보완을 승인했다. 전체 기획서 원문은 남아 있었으나 변주 출력 경로와 화면이 별도 양식을 사용하면서 기존 기획서에 접근할 연결이 빠져 있었다.

## 화면 변경

같은 변주 검토 화면에 기존 9절 전체 기획서를 먼저 표시한다. `전체 기획서 · 육하원칙`과 `이번 초반 수정안` 이동 링크를 제공하고, 기획서 각 절에서 현재 변주 문서의 관련 항목으로 바로 이동할 수 있게 했다. 독립 심사 상세는 접어 두었다.

기준안은 수정 전 원문으로 표시한다. 현재 금융형의 1992년·19세·한수경을 기준안의 1990년·17세·초기 4인 팀과 자동으로 합치지 않는다. 장기 전개가 새 도입에 맞춰 이미 재설계됐다고 표시하지 않는다. 변주 방향을 선택한 뒤 같은 9절 양식으로 통합 기획서를 작성할 작업은 남아 있다.

기준 연결은 `slateId + candidateId + projectPlan.markdown`의 원문 SHA로 확인한다. 원본 후보 파일 해시와 Storyyard 후보 투영 해시는 계산 대상이 달라 직접 비교하지 않는다. 정확한 기준을 찾지 못하면 다른 제목의 문서로 대체하지 않고 누락을 표시한다. 완료된 기준 패킷도 본문은 비교할 수 있지만 비활성 판정 화면 링크는 제공하지 않는다. 무효화된 패킷과 로그인·관리자 경계는 기존 경로를 따른다.

각 절의 연결은 수정 적용을 뜻하지 않는다. 기존 기획서 원문과 현재 변주 본문을 모두 보존하며, 판정은 계속 현재 변주 후보에만 기록된다.

## InkOS 연결

새 `pitch-variation prepare` 요청에 `planningGuidanceVersion: webnovel-bounded-variation/v1`을 기록한다. 생성·별도 심사·허용 범위 부분수정에 공통 기획 모듈의 인물·사적 목적·현장·시점·우위 사용·자기 몫과 장기/구간/회차 연결 지침을 전달한다. 변주가 기존 기획의 선행 조건과 이후 구간에 미치는 영향을 기존 필드에 설명하게 한다.

기존 실행은 버전 표지가 없으므로 이전 프롬프트 바이트를 그대로 재현한다. 새 버전의 문구도 고정해 미래 지침 변경이 과거 호출 증거를 깨뜨리지 않게 했다. 전체 기획서 재생성이나 사람 선택을 가정하는 지침은 넣지 않았다.

- InkOS 관련 검사 54/54와 CLI 빌드 통과. 기존 프롬프트 4종 해시를 유지했다.
- 기존 두 실제 실행 verifier 통과. 원 생성·심사 응답, 후보, 수정 계보, 패킷, 보호 파일과 사람 선택 대기를 보존했다.
- Storyyard 빌드 성공, 검사 71개 통과·실패 0·선택적 v3 생산자 fixture 검사 1개 건너뜀.
- 실제 두 변주 후보 모두에서 전체 기획서 9절과 육하원칙 노출, 현재 후보의 실제 섹션을 가리키는 링크, 미선택 판정 상태를 서버 렌더링 검사로 확인했다.
- 잘못된 기준 해시·슬레이트·후보 및 변경된 기획서 원문은 연결하지 않는다. 기존 패킷 17개와 인덱스·무효화 목록·호스팅 설정 등 21개 파일이 배포 전 소스와 바이트 동일하다.
