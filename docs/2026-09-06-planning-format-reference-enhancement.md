# 내부 기획서 보강 · 참고 작품과 인물·완결 연결

2026-09-06

사용자가 제공한 《칼맞고 나니 퇴마가 너무 쉬움》 투고 시놉시스 HWP 본문을 현재 기획서와 비교하고, 수용한 보강 사항을 [기존 v1 양식](templates/webnovel-project-plan-v1.md)에 반영했다. 후속 지시에 따라 차별점은 기획 항목이나 장점·심사 기준으로 요구하지 않는다. 어떤 작품을 참고했고 무엇을 가져와 쓰는지 정리한다. 참고 문서는 시놉시스이며 해당 작품의 원고를 읽었다는 뜻은 아니다.

## 양식 변경

- 1절: 참고한 작품과 가져올 요소. 이용 등급·작품 이력·현재 집필 분량은 선택 항목.
- 4절: 주인공을 계속 보고 싶은 이유와 이를 보여 주는 행동. 자기 인식과 외부 평가 차이는 해당 작품에 있을 때만 작성.
- 5절: 같은 문제를 일반 인물과 주인공이 해결하는 방식, 사건에 영향을 주는 세력의 목적·자원·이해관계. 별도 능력 체계를 의무로 만들지 않음.
- 6절: 구간에서 얻은 것이 다음 행동을 가능하게 하는 연결과 완결 시 주인공의 삶. 최초 욕망의 충족 또는 변화 이유를 확인하고 미정인 결말은 미정으로 유지.
- 8절: 참고 작품·확인한 자료와 범위·가져올 요소·채택 이유·반영 위치·필요한 조정. 원고 직접 열람과 시놉시스·분석 자료 열람, 참고 예정을 구별.
- 최종 읽기: 인명·세력명·능력·각성 시점·사건 순서의 일관성, 소개의 약속과 결말 연결, 참고 범위의 정확성.

본문 9절과 부록을 유지했다. 참고작과 다르다는 사실 자체에는 가치를 부여하지 않으며, 없는 참고작이나 착각 구도·능력 성장·확정 결말을 칸 채우기용으로 추가하지 않는다.

## 실행 지침

InkOS의 `packages/core/src/planning/webnovel-plan-format.ts`에서 일반 피치·심사·작품 설계와 후속 단계에 보강 지침을 전달한다. 기존 출력 키를 유지하며 전체 기획서는 9절, Architect는 다섯 SECTION을 사용한다. Arc·회차·원고는 현재 사건에 필요한 내용만 이어받는다.

새 변주 요청은 `webnovel-bounded-variation/v3`를 사용한다. 생성·심사·허용 범위 부분수정에 보강 내용을 전달하며, 제목 예시와 `variationQuality`의 심사 안내도 참고 요소의 적합성과 읽는 재미를 중심으로 바꿨다. 기존 v1·v2 지침은 보존하고, v2와 v3 모두 기존 전체 기획서 검증·표시 경로를 사용한다. 과거 요청을 새 지침으로 자동 재해석하지 않는다.

## 검증과 적용 범위

Core 기획서·변주 검사 21개, CLI 변주 생성·수정·복구 검사 43개가 통과했다. Core·CLI 빌드와 두 저장소의 `git diff --check`도 통과했다. 과거 v1·v2 단계별 지침 해시와 기존 무버전·v1 프롬프트 해시를 검사하고, v2·v3의 전체 기획서 검증·표시·검토 패킷 경로를 확인했다.

검사는 모델 대역을 사용했다. 실제 생성 품질은 이번 검사로 판정하지 않았다. 변경은 로컬 양식·지침·검사에 반영했으며 기존 작품·후보·원고를 재작성하거나 커밋·푸시·게시하지 않았다.
