# 현대판타지 12경로 기획 카나리

## 범위와 공통 입력

사용자가 최신 로컬 기획서 양식을 지정하고, 웹 3경로·Hermes 작성 3경로·OpenCode 무료 6모델의 실제 카나리와 Storyyard 검토/칸반 반입을 요청했다. 이번은 현대판타지 1회 비교다. 반복 일정이나 원고 작성, InkOS 정본 적용은 포함하지 않는다.

최신 `docs/templates/webnovel-project-plan-v1.md`의 부록 전 1~9절을 사용한다. WHAT은 작품 전체의 목표와 결과, HOW는 우위를 이득으로 바꾸는 반복 원리다. 차별점을 장점·심사 기준으로 강요하지 않는다.

공통 원작 묶음은 《독식하는 재벌 3세》·《금수저 투자백서》·《연봉 1조 신입사원》이다. 각 작품의 Reference Lab 역설계 기획서와 원문 앞 7,000자 발췌를 제공했다. 원문 전체를 읽힌 시험이 아니다. 공급 파일·발췌·역설계·양식의 SHA-256은 입력 영수증에 기록한다.

- 공통 입력 SHA-256: `f5509d0d0757450a781f82c7766e1b71137b3cbd8a8f09e917ed4a5545e1c8d2`
- 입력 크기: 107,597바이트
- 결과 디렉터리: `edge_repos/v3_ff_foundry/20_model_runs/multi_provider/modern-fantasy-20260906-v1/`
- 실행 스크립트: `.firefly/multi-provider-canary-20260906/run_cli.py`
- 집계 스크립트: `.firefly/multi-provider-canary-20260906/assemble.py`

## 비교를 해석하는 범위

동일 입력이지만 서비스별 시스템 지침·컨텍스트 처리와 도구 실행 방식은 다르다. 이 카나리는 각 경로의 실사용 가능성과 결과를 확인하는 것이며 모델 성능 순위를 확정하는 시험이 아니다. 사용자가 HIL로 내용과 취향을 판단한다. 본문은 다른 모델이 대신 고쳐 쓰지 않는다.

웹은 ego lite로 파일을 첨부하고 ChatGPT 6 Pro, Grok 전문가, Gemini 3.1 Pro Extended를 선택했다. 웹 화면에 없는 정확한 내부 모델 식별자·토큰·비용은 추정하지 않는다.

CLI 첫 시도 중 OpenCode의 계획 에이전트가 질문·작성 계획만 반환하는 문제가 있었다. 후속 시도는 별도 임시 디렉터리의 기획서 작성 에이전트와 도구 비활성 설정을 사용했다. 첫 응답은 `*-attempt1`에 보존한다. Ling은 이전 계획 모드에서 본문을 반환했으며 계획 도구 호출이 있었다. 따라서 해당 차이도 영수증에 남긴다.

Grok CLI는 긴 입력을 파일 참조로 바꾸는 전처리 때문에 제한된 턴 안에 읽기만 하고 끝났다. 첫 두 시도를 보존하고, CLI가 문서화한 `--verbatim` 옵션으로 입력을 그대로 전달하는 교정을 추가했다. 전처리 실패를 작가의 기획 능력 실패와 혼동하지 않는다. `--verbatim` 시도는 Hermes 터미널의 420초 제한으로 최종 응답·하위 영수증이 회수되지 않았다. 따라서 이 배치에서 Grok CLI 본문 생성 성공을 주장하지 않는다. 고정 실행기와 비동기 작업 추적이 먼저 필요하다.

Astra 직접 작성 첫 시도와 Nemotron 두 모델은 390초 제한 안에 본문을 받지 못했다. Astra는 동일 입력 재시도에서 562.5초 만에 본문 24,277자를 받았다. 원응답은 표 대신 항목형이며, 기존 1~9절 제목에만 Markdown 표시를 붙여 같은 목차로 렌더링한다. 표시 본문 해시와 원응답 해시는 구분한다. 무료 모델의 시간 초과를 영구 사용 불가로 해석하지 않는다.

## 영수증과 HIL

Storyyard의 기존 검토 칸반에 별도의 기획 카나리 카드로 표시한다. 제목·작성 경로·요청 모델·추론 모드·응답 상태와 실행 영수증을 제공한다. 각 판정은 입력 해시와 실제 표시 본문 해시에 묶인다. 선택·보류·반려는 `pending` HIL 기록이며 InkOS 정본이나 집필 명령으로 자동 적용하지 않는다.

실행 성공, 9절 형식 충족, 작품 품질 승인은 서로 다른 사실이다. 빈 응답·형식 손상도 삭제하거나 다른 모델 결과로 대신 채우지 않는다. 영수증은 원응답 파일 해시, 실행 시간, 서비스 세션, 제공자 사용량과 Hermes 관리 호출 사용량을 구분한다. Grok의 비용 수치는 CLI 보고값이며 실제 추가 청구액으로 확인하지 않았다. OpenCode의 비용 0도 Hermes 관리 호출 자원을 포함한 총비용 0을 뜻하지 않는다.

## 다음 공정에서 줄일 낭비

고정 CLI 실행마다 Hermes 에이전트를 새로 띄우면 관리 컨텍스트를 반복 소비한다. 일상 운용은 결정적인 실행기가 경로를 호출하고 Hermes가 실패·입력 선택·검토 조정만 맡는 방식이 유리하다. 이번에는 요청한 경로의 연결 증빙을 위해 관리 영수증을 별도로 확보했다. 전역 모델 설정이나 기존 InkOS/Hermes 생산 설정은 변경하지 않았다.

장르와 원작 묶음 로테이션은 다음 배치에서 결정한다. 이번 기획서에 대한 실제 HIL을 먼저 받는다.

관리용 Hermes 실행 12건의 제공자 보고 `total_tokens` 합계는 225,211이다. 캐시를 포함한 보고값이며 현금 청구액과 동일하지 않다. 작성 사용량은 각 경로의 별도 영수증을 참조한다.
