# p01 기준 사건 변주와 구간 HIL 구현

2026-09-06 · 사용자 실행 지시: 후속 작업 1~6 진행, 모델 설정 제외.

## 이번에 만들 결과

p01 기획서는 원작의 중심을 복원한 기준안으로 보존한다. 초반 1~4화와 첫 투자 회수까지의 실제 사건을 다른 원문의 사건 및 배치로 재설계한 2~3안을 만들고, 원문 근거와 함께 사람이 비교할 수 있게 한다. 이번 선택의 의미는 변주 방향 선택이다. 전체 기획 확정이나 실제 작품·A/B레일·원고 생성과 구분한다.

## 유지와 변경

보존 단위는 주인공의 자기 목적 → 개입 이유 → 가진 우위의 사용 → 자기에게 돌아오는 이익 → 독자가 즐기는 구체 행동·반응 → 다음 목적이다. '유능함 시연' 같은 태그만 일치해서는 충분하지 않다. 남을 돕고 칭찬받는 것으로 원했던 자기 몫을 대신하지 않는다.

사건의 장소·상대·문제·행동·투자 대상·사업·획득 방법을 바꿀 수 있다. 실제 사건과 서술의 순서도 필요한 선행 조건 및 보상 연결을 함께 고치면 바꿀 수 있다. 의도한 변경과 원문을 잘못 복원한 오류는 별도로 판단한다. 보조 원작에서 사건을 가져오더라도 그 주인공의 가치관을 자동으로 이식하지 않는다.

원작의 사실 복원에서는 실제 가족 보호·배려나 능력의 한계를 숨기지 않는다. 신작에서 바꾼 사실을 원작 사실이라고 기재하지 않는다. 변경 비율, 무조건적인 새 고난, 회차별 사람 승인 규칙은 추가하지 않는다.

## 구현 순서와 담당 경계

1. InkOS의 기존 source-first 생성·심사 및 상업 피치 스킬을 위 기준에 맞춘다. 기존 근접 복원 자료는 계속 읽을 수 있게 한다.
2. Reference Lab에서 주축과 보조 작품의 실제 연속 사건을 읽고, 출처 좌표·자기 이익·쾌감·필요 자원과 후속 연결을 기록한다. 이번 독해 범위만 검증했다고 표시한다.
3. 형식 안내, 심사 입력의 생성자 자기평가 노출, 기획 본문에 과다한 운영 설명을 수정한다.
4. InkOS에 구간 변주 생성·비교 경로를 추가한다. 필요한 원문과 해당 범위만 입력하고, 전체 9절 기획서를 후보마다 다시 만들지 않는다. 기존 모델 및 추론 설정을 그대로 사용한다.
5. Storyyard의 기존 검토 화면에 구간 변주 비교와 선택 의미를 연결한다. 구형 패킷의 의미를 바꾸거나 새 용어 체계를 만들지 않는다.
6. 실제 두 안 이상 생성, 별도 세션 원문·변주 심사, 로컬 검토 자료를 준비한다. 사람의 실제 선택과 이유가 오면 선택안·탈락안을 함께 사례로 남길 수 있게 한다.

## 완료 근거

- 의도적 사건 변경을 원작 사실 오류로 오판하지 않는 회귀 검증.
- 출처·좌표·원문 변경, 누락된 선행 조건, 없는 후보 선택, 오래된 후보에 대한 선택을 검증하는 적절한 검사.
- 최초 p01, 과거 카나리, 모델 설정의 보존 확인과 각 Git root의 상태 보고.
- 실제 생성·심사 입력과 사용량 기록. 캐시와 추론 토큰은 부분집합으로 처리한다. 구간 실험과 이전 전체 기획 실험의 분량 차이를 명시하고 모델 우위나 장편 절감률로 일반화하지 않는다.
- 비교 문서, 선택 대기 상태, 남은 전체 기획·A/B레일·원고 작업을 명확하게 보고한다.

기존 dirty 작업을 보존한다. 이번 범위에는 모델 변경, 원격 배포, 커밋·푸시가 포함되지 않는다. 로컬 구현과 실제 검토 가능한 변주안까지 진행한다.
