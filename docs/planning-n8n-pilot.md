# 로컬 n8n 기획 노드 파일럿

2026-09-08. 기존 Astra 기획 한 건의 입력과 응답을 실제 n8n 실행 노드에서 펼쳐본다.
현재 단계는 **과거 실행 재현**이다. 새 기획 생성이나 일일 예약 이전은 구현 범위가 아니다.

## 열기와 실행

- 화면: http://127.0.0.1:5678/workflow/ffPlanningReplay1
- 워크플로: `Firefly · 기획 흐름 살펴보기 (기존 기록)`
- 기본 자료: `hardening-canary-20260908-v1/astra`, 「이번 생은 내가 사장」.
- **Execute workflow**를 누르면 노드 전체가 실행된다. 노드를 더블클릭하고
  Output의 JSON 또는 Table에서 그 단계의 실제 결과를 읽는다.
- 실행 기록은 Executions에 남는다. 성공 표시는 데이터 처리 성공이다.
  재미·채택·게시 성공을 뜻하지 않는다.
- 로컬 전용 계정은 `.firefly/n8n-pilot/owner-login.json`에 있다.
  자격 증명·데이터베이스·입출력 사본은 Git 제외 경로에만 저장한다.

```sh
python3 scripts/planning-n8n.py start
python3 scripts/planning-n8n.py status
python3 scripts/planning-n8n.py stop
```

시작은 수동이다. 재부팅 후 자동 실행을 등록하지 않는다. 중지는 파일과 이력을 보존한다.
설치된 n8n을 재사용하되 사용자 데이터는 기존 `~/.n8n`과 별도 경로로 격리한다.

## 실제 노드와 데이터

| 노드 | 수행하는 일 |
| --- | --- |
| 기록 선택 | 등록된 기획 결과 경로의 완료된 Astra 기록을 선택하고 입출력 해시 대조 |
| 원문 · 분석 발췌 | 당시 입력에 보존된 원문 발췌와 분석 텍스트 읽기 |
| 기획 양식 · 당시 지침 | 당시 실제 전달된 지시와 양식 읽기 |
| 당시 사용자 의견 | 당시 입력에 포함된 의견과 적용 범위 안내 읽기 |
| 입력 조립 · 해시 대조 | 앞 세 노드의 실제 출력으로 원래 입력을 다시 조립하고 해시 대조 |
| 기존 Astra 응답 읽기 | 독립 보존 원응답과 기획서의 일치를 확인한 기존 응답 읽기 |
| 기존 형식 검사 실행 | 현재 `planning-input.py`로 9절·육하원칙·빈칸 검사 재실행 |
| 원본 보존 · 검증 기록 | 원본 파일 보존, 입출력 해시, 검사 결과와 새 모델 호출 0회 기록 |

정보격차·욕망·보상은 이 워크플로의 별도 모델 호출 단계가 아니다.
양식에 들어 있는 개념을 독립 실행 노드로 위장하지 않는다.

입력을 수정하거나 잘못된 과거 응답을 붙이면 실행을 중단한다. 원래 응답을
바뀐 입력의 생성 결과로 표시하지 않는다. 임의의 현재 원문이나 다른 날짜의
사용자 의견으로 과거 실행을 재구성하지 않는다. 표시되는 기존 사용량과
이번 실행의 새 모델 호출 수를 구분한다.

## 연결과 소유권

- HQ: 호출 어댑터, 워크플로 정의, 로컬 관찰 기록.
- V3 Foundry: 기존 입력·기획서 정본. 읽기만 한다.
- Reference Lab: 당시 입력에 참조된 분석·원문 소유권을 유지한다.
- InkOS, Storyyard, Notion 및 예약 실행기는 호출하지 않는다.

n8n은 `127.0.0.1:5678`, 로컬 어댑터는 `127.0.0.1:5679`, n8n 내부 task broker는
`127.0.0.1:5680`을 쓴다. 어댑터의 자료 조회와 단계 실행은 별도 토큰을 요구한다.
n8n은 HTTP Request 노드로 어댑터를 호출한다. 임의 셸 실행이나 Python Code
노드를 활성화할 필요가 없다. n8n의 내부 Python task runner가 없는 설치에서도
이 파일럿은 기존 시스템 Python 어댑터를 사용한다.

- 정의 생성: `python3 scripts/planning-n8n.py export`
- 로컬 이력: `.firefly/n8n-pilot/user/.n8n/database.sqlite`
- 검증 기록: `.firefly/n8n-pilot/replays/<runId>/08-receipt.json`
- 재현 입력 및 노드 결과: 같은 폴더의 `context.json`, `01-*.json`부터 `08-*.json`.
- 테스트: `python3 tests/planning-nodes.test.py`

후속으로 새 생성까지 연결하려면 별도 실험 ID, 변경 입력 보존, 기존 작성기
작업 ID와의 중복 방지, 비용 상한, 중단 처리를 추가한다. 현재 파일럿의 재현
성공은 이 새 생성 경로가 구현됐다는 뜻이 아니다.

## 2026-09-08 검증 결과

- 설치된 n8n 2.20.9를 재사용했다. 패키지 갱신과 외부 계정 가입은 없었다.
- 실제 n8n 화면에서 수동 실행 1번이 성공했다. DB의 실행 ID `1`은
  `status=success`, `mode=manual`, `finished=1`이며 워크플로는 비활성이다.
- 8개 처리 단계와 수동 트리거의 성공 표시를 화면에서 확인했다.
  응답 노드의 Input에 원래 프롬프트, Output에 「이번 생은 내가 사장」
  본문과 과거 사용량·이번 새 모델 호출 0회가 표시된다.
- 재현 ID: `c4a62269173c486da4578ce3a90c9b1a`.

- 출력 SHA-256: `cd6c2cdf4db11333d9b2333d1d7b8fbe25962775f897a289bb01f3eef364f5a1`.

  입력 손상, 원응답 불일치, 실행 도중 원본 변경, 경로 이탈,
  단계 재시도, 무인증 요청과 미구현 생성 요청 거절.
- n8n·어댑터·task broker는 모두 `127.0.0.1`에서만 수신함을 확인했다.
- 코드와 운영 메모는 로컬 변경이며 커밋·푸시는 수행하지 않았다.
