# 작품별 주인공 배경과 목적 연결 개선

2026-09-06 · InkOS 로컬 구현

요청은 특정 작품의 정답을 기획서에 대신 써 주는 것이 아니라, InkOS가 작품마다 주인공의 출발 배경·이전 경험·현재 상황을 읽고 자기 목적과 선택의 이유를 챙기게 만드는 것이다. 기존 기획은 욕망·목표·행동을 따로 요구했지만 그 앞의 삶과 자원이 이 선택을 가능하게 하는지는 짧은 인물 소개에 맡겨져 있었다.

## 반영한 동작

1. 생성 지침은 원문에서 배경·경험·현재 자원과 관계를 복원하고, 개인 목적→선택→수단으로 연결한다. 원작 설명은 `sourceReconstruction.protagonist/sourceChoice`, 신작 설명은 `startingIdentity`, 목적·우위·도입 사건과 기획서에 담는다. 기획서의 인물 소개와 이야기 출발은 자연어로 읽히게 하고 상세 좌표는 참고 근거에 모은다.
2. 새 `pitch slate --source-first` 실행은 호스트가 `protagonistContextPolicy: protagonist-context/v1`을 기록한다. 기존 작성 호출과 별도 독립심사 호출을 사용하며 새 모델 호출 단계를 추가하지 않는다.
3. 독립심사는 각 후보에 배경·경험·현재 상황의 확인 상태, 원문 좌표, 원작/신작 인과 설명, 실제 후보 필드 위치를 남긴다. 원작 사실, 목적과 수단의 연결, 기획 본문의 설명을 각각 판단한다.
4. 코드가 참조 파일과 실제 행 범위, 후보의 존재하는 문자열 위치, 필수 연결 범위, 판정 간 모순을 검사한다. 생성 당시 원문 해시와 slate 해시는 기존 결속을 사용한다. 이 검사는 심사 저장 직전과 Storyyard 내보내기·사람 선택 기록을 위한 재읽기에서 모두 실행된다. 사실 교정으로 새 기획안을 만드는 경로도 원래 정책 값을 보존한다. 미지원 버전을 옛 기준으로 낮추지 않으며, 이전 기획안에는 새 검증 표시를 만들지 않는다.
5. 관련 연결은 작품 설계·A/B레일 관련 기획·회차 메모·원고 지침에도 이어진다. 현재 사건에 쓰이는 사실만 가져오며 매 화 생애 설명을 반복하지 않는다. 사건 변주 경로에서도 배경과 수단의 출처를 확인하고, 보조작 주인공의 과거 경력을 자동 이식하지 않는다.

## 작품마다 달라야 하는 것

- 풍족한 가정, 평온한 과거, 충분한 재산과 능력도 정상적인 출발이다. 회귀·트라우마·실패·결핍·능력에 의한 약점 보완을 의무로 삼지 않는다.
- 원문 미공개, 제공 범위에서 미확인, 해당 없음은 서로 다르다. 조사한 범위를 남기고 그 상태 자체를 실패로 처리하지 않는다.
- 승인된 신작 배경·사건 변주는 허용한다. 새 설정을 원작의 사실로 위조하거나, 없는 과거를 만들어 수단의 출처를 정당화하면 지적한다.
- 배경의 모든 사실을 모든 행동의 원인으로 연결하지 않는다. 현재 목적과 선택을 이해하는 데 실제 필요한 관계를 복원한다.
- 본문 설명이 부족한 경우와 원작 사실이 틀린 경우를 구분한다. 본문 연결 검사만 실패하면 원작 사실 판정을 자동으로 실패시키지 않는다.

## 계약과 보존

`webnovel-project-plan/v1`, spine v2, Storyyard 기획 HIL v3 및 변주 HIL v5는 유지한다. 추가 기록은 InkOS 독립심사 내부 자료이며 Storyyard의 엄격한 계약에 새 키를 넣지 않는다. 기존 기획서의 자연어 내용과 기존 심사 근거가 계속 Storyyard에 전달된다.

이전 slate는 새 검사를 받았다고 간주하지 않고 기존 계약으로 읽는다. 내용을 자동 보충하거나 해시를 바꾸지 않는다. 기존 p01, 원문, Reference Lab 분석, 모델 설정과 Storyyard 배포는 이번 변경 대상이 아니다. source-first Book 승격의 기존 미지원 경계도 유지한다.
