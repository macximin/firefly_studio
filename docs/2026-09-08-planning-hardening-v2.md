# 일일 기획 공정 개선 · 2026-09-08

사용자 승인: 전체 점검에서 확인한 개선 사항 구현, 배포, 웹 회수 부분 카나리 후 동일 입력 6경로 검증.

## 구현

- 실행 중단: 종료 직전 제어권 표식도 실패/중단으로 판정한다. 작성자·Copy·Ego·대기 프로세스의 작업별 그룹을 실행 전 등록하고, 종료 신호·시간 초과 때 정리한다. 브라우저 잠금 대기는 busy/pending, 실제 동작 중단은 별도 오류로 기록한다. 등록 경로를 우회하는 프로그램까지 막는 OS 샌드박스는 아니다.
- 기획 입력: 회귀·재벌 설정을 일괄 강제하지 않는다. 기존 검증된 6작품의 3작품 조합 20개를 순환하며, 같은 날 6경로는 같은 입력을 받는다. 참고작별 기존 사건·보상 분석 발췌와 원문 앞 7,000자를 구분해 출처·범위·해시를 보존한다. 전체 원문 독해로 표시하지 않는다.
- 양식: 사용자의 9절과 육하원칙을 유지하고, 부록 뒤 최종 읽기 지침도 전달한다. 빈 절·빈 답란·원본 자리표시자는 완료 처리하지 않는다. 사람의 재미 판단과 채택은 자동 판정하지 않는다.
- HIL: 원본 결정과 ID/해시를 보존한다. 같은 후보의 최신 의견, 반복 의견의 각 대상, 대체된 의견, 명시적 운영 시험을 구별한다. 작품별 코멘트를 자동으로 전역 취향이나 새 작품 승인으로 승격하지 않는다.
- 영수증: 요청 모델·관측 모델·관측 모드·확인 수준을 분리한다. Astra는 호출 전 Hermes revision/파일 hash/어댑터 hash와 medium 요청을 기록한다. 기존 불변 패킷은 재수집으로 바꾸지 않는다.
- Storyyard: 실제 출처·시도·복구 관계 표시, 가벼운 목록 조회, 페이지 넘김, 서울 실행일·경로 검색, 관리자 보관/복원. 보관은 별도 D1 메타데이터이며 본문과 HIL을 바꾸지 않는다. 이전 판정은 복구본의 승인으로 승계되지 않는다.
- 예약: 기존 전용 LaunchAgent의 02시 시작을 유지하고 5분 재점검 및 로그인 후 확인을 추가했다. 완료된 오늘 배치는 모델/Notion 호출 없이 건너뛴다. 사전 조회 오류는 서울 날짜별 최대 3회, 기존 배치 회수도 최대 3회다. 복구는 누락 작성기를 새로 제출하지 않는다. 과거 배치 회수가 오늘의 새 실행을 소비하지 않는다.
- 명시적 카나리는 `--canary NAME`, Notion `구분=카나리 검증`으로 일일 배치와 구별한다. `--reconcile`은 신규 작성 없는 회수 전용이다.
