# 문체 도구 연결과 후속 작업 · 2026-09-08

사용자 요청: 기존 작업과 병렬 진행 가능 여부, GitHub `im not ai` 연결 계획,
내부 추가 개선 조사, 후속 목록 작성 후 goal로 처리.

**현재 상태: 사용자 요청으로 안전 중지.** 기획서 4편 게시, 웹 2편은 대화 주소를
보존했다. 예약·운반 프로세스를 중지했으며 문체 진단 응답은 검증 대기다.
재개 절차는 [체크포인트](../.firefly/checkpoints/planning-pause-20260908/RESUME.md)에 있다.

## 판단과 작업 분담

기획 카나리의 입력과 산출물을 고정하면 병렬로 진행할 수 있다. 현재 운반·예약
수리는 HQ 실행기, 문체 도구는 별도 읽기 전용 검사기, Storyyard는 이미 배포한
검토 화면을 사용한다. 별도 작업을 의미하는 ‘디존’의 정확한 범위는 확인 중이며,
그 작업의 파일이나 세션을 임의로 수정하지 않는다. 브라우저 조작은 현재 운반
작업자에게만 맡긴다.

`im-not-ai`의 정확한 저장소는 <https://github.com/epoko77-ai/im-not-ai>다.
9월 3일 내부 조사에도 후보로 기록됐으나 실행 연결은 보류 상태였다.
이번에는 현재 revision을 고정하고 실제 호출 가능한 검사기를 붙인다.

이 도구는 한국어 표현을 살피는 데 도움이 된다. 주인공의 자기 이득, 욕망에서
단기·장기 목표로 이어지는 인과, 원작의 재미를 조합하는 설계는 별도 검토 대상이다.
문체 점수가 그 판단을 대신하지 않는다. 기존 humanizer, avoid-ai-writing,
deslop를 연달아 돌려 작품을 여러 번 재작성하지 않는다.

## 문체 도구 적용 계약

1. 고정한 upstream의 한국어 규칙과 원시 지표를 사용한다. 파일 해시가 달라지면
   조용히 새 버전을 적용하지 않는다.
2. 결과는 ‘수정 검토 후보’와 해당 위치·근거다. AI 작성 판정이나 품질 합격 점수로
   부르지 않는다. upstream의 미보정 기준값은 웹소설 기준으로 쓰지 않는다.
3. 짧은 문장, 대사, 의도적 반복, 거친 인물 말투를 일괄 교정하지 않는다.
   장문 삽입을 강제하지 않는다.
4. 기획서의 9절, 육하원칙 표, 고유명사, 인용 원문, 참고 범위, HIL 및 영수증을
   보존한다. 입력 파일을 직접 고치는 기능은 두지 않는다.
5. 전역 스킬 설치만으로 Hermes·Grok·agy·웹이 자동으로 읽는다고 가정하지 않는다.
   공정에서 호출하는 명시적 어댑터와 산출물 경로로 연결 여부를 증명한다.

## 다음 단계의 판단 항목

- 웹소설 문장과 기획서 문장을 나눠 오탐을 확인한다. 원작의 의도된 대사·호흡까지
  잡아내는 규칙은 관찰 전용으로 남기거나 적용 대상을 좁힌다.
- 현재 규칙을 모든 작가에게 미리 주입하는 실험은 이번 비교와 분리한다.
  같은 원고의 최소 수정 후보를 비교해 독자 보상·인물 음성이 보존될 때만 확대한다.
- 운반 모델의 토큰은 작성 모델과 구별한다. 완료 후 전문 재독해를 줄이고,
  예외가 없을 때는 고정 검사기가 처리하는 비율을 늘린다.
- 실행기 파일은 실행 시작/종료 시 해시로 확인한다. 다른 작업과 공정이 커지면
  배치별 실행 버전을 완전히 고정하는 방식을 검토한다.
- 현대판타지 참고작 풀은 현재 재벌·투자 계열 6작품이다. 20개 조합 순환은
  조합의 반복을 줄이지만 소재 폭까지 넓히지는 않는다. 다른 현대판타지 제재와
  판타지·무협의 검증된 참고작 풀은 별도 준비가 필요하다.
- 현재 일일 설정은 6경로다. 하루 10편 확대는 회수 성공률·실제 관제 사용량·HIL
  결과를 보고 작성 경로와 편수를 정할 항목으로 남긴다.
