## 작성과 대기

CLI는 다음 고정 실행기를 사용한다. 입력 파일과 새 결과 디렉터리는 실제 배치 경로로 지정한다.

```sh
python3 scripts/planning-process.py start --route grok-cli --input INPUT_PATH --directory NEW_JOB_PATH --timeout 3600
python3 scripts/planning-process.py status --directory NEW_JOB_PATH
```

지원 경로는 `astra`, `grok-cli`, `gemini-cli`, `grok-supervisor`, `chatgpt-web`, `grok-web`, `gemini-web`다. 웹 3경로는 Grok이 에고 브라우저로 운반하며, 웹 서비스가 기획서 작성자다. 원문을 Grok의 대체 창작으로 채우지 않는다. 호출마다 실행 ID·입력 해시·원출력·종료 코드·시간을 남긴다. 기존 디렉터리 재사용은 거부한다. 반환 후 별도 프로세스로 실행되므로 관제 터미널의 420초 제한에 묶이지 않는다. 상태가 running인데 workerPid와 writerPid가 사라졌으면 중단/미확인으로 처리하고 즉시 중복 제출하지 않는다.

프로세스 완료는 기획서 완료가 아니다. 서비스 JSON에서 실제 응답과 사용량을 추출하고, Astra는 scripts/planning-astra.py 문서 전용 Hermes 어댑터로 medium을 명시하고 실제 요청의 reasoning을 기록한다. 터미널용 plain-text 지침을 사용하지 않는다. Hermes 출력은 최종 assistant 본문과 대조한다. 9절·WHO/WHAT/HOW/WHERE/WHEN/WHY를 검사한다. 본문을 몰래 보완하지 않으며 추출 전 원응답을 보존한다. 출력이 없으면 보고 토큰 수가 있어도 본문 성공이 아니다.

웹은 ego-browser 스킬과 사용자가 지정한 브라우저를 사용한다. 실제 가용 최고 추론 모드를 확인하고 동일 입력을 전달한다. 완료 응답과 서비스 대화 링크를 회수한다. 일반적으로 30분, 고추론은 최대 60분까지 진행 상태를 관찰한다. 관측 불가를 실패로 단정하지 않는다. 사용자 브라우저 제어·로그인 요청이 생기면 해당 경로를 멈추고 남은 독립 경로를 처리할 수 있는지는 스킬의 실제 지침을 따른다.

## 2026-09-08 개선 2차

- 입력은 `planning-input.py`가 만든다. 기존 6개 참고작에서 3개씩 고르는 20개 조합을 순환하며, 하루의 6경로에는 동일 입력을 전달한다. 원작 유형을 무시한 회귀·가문·회사 조건을 공통으로 강제하지 않는다. 최종 읽기 지침과 필요한 기존 사건·보상 분석 발췌를 포함한다.
