## 운영 원칙

HQ·InkOS·Reference Lab의 소유권을 유지한다. 현재 작업은 코드·자료·격리 fixture의 구현과 검증이며 기존 Book 원고를 임의로 재생성하거나 승인값을 만들지 않는다. 기존 검증된 입장을 소비하는 새 경로는 구현할 수 있지만, 부족한 출처나 A/B 매핑을 추측으로 채우지 않는다.

각 묶음을 마칠 때 변경 경로·실제 검증·남은 한계를 갱신한다. 이전 검증 영수증의 해시를 새 코드의 통과 증거로 재사용하지 않고, 바뀐 경로에 필요한 검증을 다시 수행한다.

## 실제 호출에서 확인한 보완

- Planner·Writer·Reviser의 창작 의도 투영은 정확한 출처와 잔여 예산을 사용한다. 기록 실패가 기존 호출을 막지 않는다. 한글 Book ID도 기존 계약으로 처리한다.
- Planner의 장면 후보는 원래 메모에 남기고, 실제 집필 문맥에는 선택한 행동과 이유만 전달한다. 잘못된 optional 기록 때문에 추가 모델 호출을 만들지 않는다.
- 기존 Settler의 독자 공개·인물 인지·보상 기록은 실제 저장 본문에 결속된다. 수정에서 본문이 바뀌면 옛 분류를 제외하고, 저장 뒤 단계의 실패는 원고와 현재 관찰 포인터를 함께 복구한다.
- 초고 발견은 일반 집필뿐 아니라 초안·복구·재동기화·반입 결과의 저장까지 연결했다. 기존 transaction 성공 뒤에만 기록하고, 다른 Book/회차·바뀐 본문·과거 조회의 미래 자료를 제외한다.
- 수정 경험은 실제 자동 심사에서 선택된 본문에 연결한다. CRLF·메모 줄·문장부호 정리가 개입해도 원래 모델 응답을 보존한 파생 기록으로 이어지고, 다음 수정에서 같은 원인일 때만 참고한다.
- 원문 기획은 canary·기획 본문·기존 선택/승인·명시 A/B/Arc/foundation 매핑을 검증한 뒤 opt-in Book 생성으로 전달한다. 합성 fixture에서 기존 입장·저장·조회까지 실행했다.

심볼릭 링크로 Book 밖에 advisory 파일이 생기는 경로도 막았다. 이는 선택적 기록의 파일 경계 검사이며 기존 원고 저장과 승인 권한을 바꾸지 않는다.

창작 의도의 `documentScopes`는 추가 투영에만 적용된다. 기존 Planner/Composer의 원문 방향 입력을 전체 차단하는 설정으로 확대하지 않았다. 이 한계는 [기능 문서](2026-09-12-book-creative-brief.md)에 명시했다.
