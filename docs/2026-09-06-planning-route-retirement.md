# 무료 기획 경로 제외와 관제 대안

> 무료 6경로 제외는 현재도 유효하다. 아래 Grok CLI 재시험 요구는 후속 검증으로 해제됐으며, 현재 경로는 `config/planning-provider-policy.json`과 [피치 정책·연결 상태](pitch-policy-status.md)를 따른다.

2026-09-06 · 사용자 후속 결정과 읽기 전용 대안 조사.

## 반영한 결정

OpenCode 무료 묶음 6개(Mimo, Big Pickle, Ling, Nemotron Ultra, Nemotron Lightning, Muse)를 후속 기획 생성 대상에서 제외한다. 국적이나 영구적인 모델 능력 판정이 아니라, 이번 운영에서 추가 교정·관제 비용을 들이지 않겠다는 선택이다. 시간 초과와 작성 품질 문제는 구분한다.

- 정책: `config/planning-provider-policy.json`.
- 기존 1회용 `run_cli.py`는 무료 경로의 직접·관리 호출을 거부하고, 일괄 호출에서도 제외한다. Grok CLI는 재시험 필요 경로로 일괄 호출에서 제외한다.
- 같은 배치의 기존 영수증을 덮어쓰는 호출도 거부한다. 새 시험은 새 배치와 실행기로 진행해야 한다.
- 기존 12개 결과·원응답·영수증·Storyyard 카드는 역사 기록으로 보존한다. 이번에는 사이트 재배포나 카드 아카이빙을 하지 않았다.
- OpenCode 설치와 기존 InkOS Hermes 설정은 유지한다.

문법 확인 및 9개 CLI 키에 대한 사전 검사로 무료 6개 거부와 기존 영수증 3개 보호를 확인했다. 모델 호출은 없었다. 이 정책은 현재 카나리 실행기에 연결했으며 별도 과거 스크립트 전체를 제어하는 전역 차단 기능은 아니다.

## 유지할 작성 경로

웹 ChatGPT·Grok·Gemini, Hermes Astra, Antigravity Gemini는 이번 배치에서 9절 본문을 회수했다. 이는 품질 채택이 아니다. Grok CLI는 유지 후보지만 관리자 터미널 420초 제한 문제를 해결한 뒤 재시험해야 한다. 자세한 증빙은 [12경로 카나리](2026-09-06-twelve-route-planning-canary.md)에 있다.

## 비용을 줄이는 권장 구성

1. 고정 스크립트가 입력 묶음, 실행 상태, 완료 감지, 원응답 수집, 해시와 형식을 관리한다. 단순 실행과 대기에 관제 LLM을 반복 호출하지 않는다.
2. 기존 구독의 GPT·Grok·Gemini가 기획을 작성한다. 웹과 CLI는 서로 다른 경로로 표시하고 계정 한도가 늘어난다고 가정하지 않는다.
3. 오류 해석이 필요할 때만 Grok에 해당 오류와 최소 맥락을 전달한다. 본문 재작성이나 모델 교체를 자동으로 숨기지 않는다.
4. Storyyard에서 사용자가 재미와 취향을 판단한다. 중요한 공정 변경과 모호한 예외만 상위 모델에 올린다.

위 관제 구성은 제안이며 이번에 구현한 것은 경로 제외와 재실행 보호뿐이다. 새 상시 감독자·예약 작업·기획 생성은 시작하지 않았다.

## 확인한 대안

로컬 `/opt/homebrew/bin/codex`는 `codex-cli 0.145.0`이며 `codex login status`에서 ChatGPT 로그인을 확인했다. `codex exec --help`는 표준입력, `--json`, `--output-last-message`, 모델 지정과 읽기 전용 실행을 지원한다. 공식 문서도 저장된 CLI 인증 재사용과 실행 이벤트·최종 응답 파일 출력을 안내한다. 따라서 새로운 관리 에이전트 없이 기존 계정으로 작성·예외 분석을 호출하는 후보로 적합하다. 이번 공통 기획 입력으로의 작성 품질은 아직 시험하지 않았다. [Codex 공식 문서](https://developers.openai.com/codex/non-interactive-mode)

OpenCode 자체에는 ChatGPT Plus/Pro 연결도 있다. 무료 모델 묶음을 버린다고 클라이언트 자체를 삭제할 필요는 없다. 다만 현재는 로그인된 공식 Codex CLI가 이미 있으므로 중간 연결을 더 늘릴 실익이 작다. OpenCode 쪽 새 인증은 수행하지 않았다. [OpenCode 공급자 문서](https://opencode.ai/docs/providers/)

## 긴 작업 대기 수선의 다음 범위

Hermes 터미널과 작성 프로세스 수명을 분리하고 작업 ID·프로세스·마지막 출력·완료 영수증으로 추적해야 한다. 일반 30분/고추론 60분은 초기 관찰 기준 제안이며 실제 측정 후 조정한다. 오래 걸린다는 이유만으로 실패 처리하거나 살아 있는 요청을 중복 제출하지 않는다. 현재 1회용 스크립트의 시간 제한은 아직 이 제안으로 교체하지 않았다.
