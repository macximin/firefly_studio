# Firefly 컨텍스트 효율 후속 작업 결과

기준일: 2026-09-05. [선행 계획](2026-09-05-context-efficiency-followup-plan.md)의 목록화→계획→구현→실행 검증을 완료했다. 현행 InkOS에는 Astra/high와 SHA로 결속한 1,219-byte 기본 지침을 적용했다. Hermes 다섯 프로필의 Astra/high 설정은 앞선 전환 상태를 유지한다.

## 처리한 후속 작업

| 작업 | 처리 결과 |
| --- | --- |
| 호출별 계측 | 요청·결과·raw usage·모델·단계·세션·지침/입력 SHA·시각을 별도 journal에 기록한다. 실패와 중단도 남기고, 미제공 값은 null이다. |
| 후보 형식 오류 | 후보 전체를 모델로 재생성하던 경로를 제거했다. 정수 문자열·합계처럼 의미 보존을 증명할 수 있는 점수 오류만 프로그램이 복구한다. 나머지는 원본과 진단을 보존한다. |
| 사실 교정 | `pitch-fact-repair prepare/run/apply`를 추가했다. 원문 근거와 지정한 문장 범위만 보내고, 모든 범위에 수정/유지 판정을 받는다. 원본 SHA·UTF-8 범위·원작 근거·의도된 변주를 검증한다. |
| Codex 기본 지침 | SHA 결속 `codexModelInstructions`를 provider와 Agent 경로 모두 지원한다. 같은 바이트를 임시 실행 환경에 복사한다. 실제 A–B–B–A 비교 후 현재 InkOS 설정에 적용했다. |
| 독립심사 역할 | 일반 채팅 지침 대신 심사/명시된 사실 교정에 맞는 역할 지침을 사용한다. 지침 자체는 5,147→1,558 bytes. `toolPolicy: none`은 실제 도구 목록과 세션 캐시에 반영된다. |
| 실제 검증 | 고정 정답 호출 4회, 기존 두 기획서의 사실 교정과 별도 독립심사, 회귀 테스트 370개 및 Core/CLI 빌드를 확인했다. |

원작의 자기이익·목적·사건·보상 근거, 기획서 9항목, WHO/WHAT/HOW/WHERE/WHEN/WHY, 기존 A/B 레일과 Storyyard 계약은 유지한다. 원문·이전 카나리·기존 심사와 사람 선택 관련 보호 파일 65개는 SHA가 동일하다. 새로운 스토리 분류나 Storyyard 계약은 추가하지 않았다.

## 실제 토큰 비교

동일 Astra/high, 같은 실행 파일·모델 카탈로그·직렬화 입력 SHA로 기본 지침과 축소 지침을 각각 두 번 실행했다. 순서는 기본→축소→축소→기본이다. 자기 지분·수익 우선, 회사/투자/채용 순서와 원문 속 명령을 데이터로 취급하는지 확인하는 합성 고정 정답 문제다. 네 번 모두 요구한 JSON 정답과 정확히 일치했다.

| 구분 | 평균 입력 토큰 | 평균 출력 토큰 | 캐시 입력 |
| --- | ---: | ---: | ---: |
| 기본 지침 2회 | 11,537 | 138.5 | 0 |
| 축소 지침 2회 | 7,647 | 129.5 | 0 |

이 작은 입력에서는 평균 입력이 **33.72% 감소**했다. 네 호출 총 사용량은 38,904 tokens다. 이 수치를 장편 전체 공정 절감률, 처리 속도, 원고 품질 개선으로 확대하지 않는다. 캐시 개선은 이번 표본에서 관찰되지 않았다.

## 실제 기획서 사실 교정 카나리

기존 v2 두 후보에서 **회사 설립→상승 수익 20억 달러→직원 25명→하락 수익 100억 달러**의 한 사실 관계를 다뤘다. 하락 투자 지시는 채용보다 앞서므로 수익 실현 시점과 따로 검증했다. 준비 중 독립 검토가 빠진 지급 순서 한 곳을 찾아 35→36개 출현부로 보강했고, 원문 근거는 5개 구간으로 결속했다.

기존 후보 JSON은 96,939 bytes, 기존 근거 묶음은 199,421 bytes다. 이번 교정 요청 본문은 59,962 bytes이며, 원문 근거 10,204 bytes와 주변 문장 9,187 bytes를 포함한다. 두 입력을 합친 크기와 교정 요청 크기는 구성 자체가 다르므로 동일 입력의 A/B 토큰 비교로 해석하지 않는다.

- 지정한 36곳을 모두 처리: 수정 10곳, 유지 26곳.
- 실제 바뀐 필드 8개. 원본과 요청을 다시 적용한 결과가 저장된 후보와 정확히 일치한다.
- 의도된 회사명 변주 2곳은 그대로 유지했다.
- 독립심사는 별도 세션에서 전체 후보·기획서와 **동일한 199,421-byte reference bundle 전체**를 받았다. 교정에 쓴 모든 정확 원문 구절이 이 묶음에도 들어 있음을 검사한다.
- 전문 751화·10,220,730 bytes는 로컬 SHA와 정확한 원문 좌표의 검증 근거다. 전문 751화 전체를 모델이 재심사했다는 뜻은 아니다.

| 실제 단계 | 입력 토큰 | 출력 토큰 | 출력 중 추론 | 입력 중 캐시 | 호출 시간 |
| --- | ---: | ---: | ---: | ---: | ---: |
| pitch-fact-repair | 26,341 | 9,341 | 2588 | 0 | 365.4초 |
| pitch-review | 97,545 | 7,733 | 2588 | 0 | 386.5초 |

추론 토큰은 출력에, 캐시 토큰은 입력에 포함되므로 중복 합산하지 않는다. 이번 실제 카나리 journal 합계는 140,960 tokens다. 앞선 고정 정답 비교까지 포함한 실제 검증 6회는 총 179,864 tokens를 사용했다. 교정과 독립심사는 각각 1회로 끝났으며 형식 재시도는 발생하지 않았다.

독립심사 결과:

- p01: **SURVIVE**, 93/100. 초반의 필수 인과 수리는 없다. 최소 표기 정리로 arcLadder[1].externalMove의 1~188화가 해당 단계의 연재 배정 범위가 아니라 원문 참고 범위임을 명시한다. 장기 가설을 실행 A/B레일로 바꾸거나 새 회차 범위를 확정할 필요는 없다.
- p02: **HOLD**, 91/100. entryContract.commercialPromise.howAdvantage의 일본 투자 결과는 도윤의 개인 투자자금과 그 실현 수익으로 귀속되며, 이후 미국 법인 설립 뒤 포트원 자금으로 투입된다는 시간 구분을 명시한다. projectPlan.markdown 제2장 HOW 행의 ‘실현 수익은 자기 회사에 남기고’도 미국 법인 설립 이후의 반복 운용을 뜻한다고 한정한다. 나머지 자금 규모·수익·인재 협상 변주는 유지하면 된다.

기존 v2의 다른 결함을 이번 한 사실 교정이 해결했다고 주장하지 않는다. 새 후보는 비정사이며 사람 선택은 pending이다. 이 실행은 공정·수정 범위·계측 검증이다. 새 전제를 생성해 기획서까지 다시 완주한 품질 카나리는 별도 작업으로 남는다.

## 운영 방법과 남은 범위

InkOS 프로젝트에서 원본 기획 slate, 원작 전문, 검토된 사실/출현부 index를 지정한다.

```sh
inkos pitch-fact-repair prepare --slate <원본-slate.json> --source <원작-전문.txt> --index <사실-index.json> --out <새-준비-폴더>
inkos pitch-fact-repair run --prepared <준비-폴더>
inkos pitch-fact-repair apply --prepared <준비-폴더> --id <새-slate-id>
inkos pitch review --id <새-slate-id> --session <새-독립심사-session> --json
```

새 fact-repair CLI는 현재 설정 모델을 사용하고 실제 모델·provider·reasoning·응답·세션·receipt를 결속한다. 코드 안에 Astra만 허용하는 제약을 넣지 않았다. 이번 Firefly 실행/현재 설정은 Astra/high다.

남은 범위는 명확하다. 사실 index는 지정 출현부 목록이며 의미상 누락을 자동으로 증명하지 않는다. 후보의 의미 누락과 파싱 실패를 해결하는 일반 재설계 기능도 아니다. 독립심사 JSON 형식 오류의 기존 전체 응답 재시도 1회는 유지하며 `pitch-review-format-retry`로 별도 계측한다. 다음 개선 판단은 이 journal에서 실제 반복 실패가 확인될 때 한다.

현재 지침은 [InkOS 기본 지침](../edge_repos/inkos/config/codex/inkos-model-instructions-v1.md)에 있으며 모델 변경 자체가 원작 이해나 글쓰기 품질의 향상을 입증하지는 않는다. 이번 결과는 원문에 근거한 판단을 유지하면서 불필요한 기본 지침과 재생성 비용을 줄일 수 있음을 확인한 것이다.
