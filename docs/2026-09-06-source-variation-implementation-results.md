## 무엇을 바꿨는가

기존 p01은 기준안으로 보존했다. 새 주인공 욕망을 먼저 발명하는 대신, 실제 원문 사건에서 자기 목적 → 개입 이유 → 우위 사용 → 자기 몫 → 구체 행동과 상대 반응 → 다음 목적을 추출해 사건을 바꾸는 공정을 추가했다. 장소·아이템·상대·해결 행동뿐 아니라 사건 배치도 바꿀 수 있다. 바뀐 사건의 정보·자금·실행자·능력·연대를 같이 설계하도록 했다.

원문 사실을 틀리게 읽은 경우와 신작을 의도적으로 바꾼 경우는 따로 심사한다. 보조 원작에서 사건을 가져와도 그 주인공의 가치관이나 특수능력까지 가져온 것으로 처리하지 않는다. 실제 원작의 가족 애정이나 타인 배려는 복원에서 숨기지 않으며, 신작의 자기 이익 우선과 혼동하지 않는다.

### InkOS

- 기존 source-first 생성 지시와 상업 피치·심사 스킬을 수정했다. 관계 변환 필드의 객체/null 예시를 실제 규격과 맞췄다.
- 기존 피치 심사 입력에서 생성자의 점수·판정 값을 분리한다. 본문의 명시적 자기평가도 정확한 문자열 구간만 가리고, 원본·심사 입력의 SHA와 제거 위치를 기록한다. 알 수 없는 중첩 평가 필드는 조용히 넘기지 않는다. 이미 입력이 있는 심사 세션의 재사용을 막는다.
- 새 `pitch-variation` 명령으로 준비 → 생성 → 별도 세션 심사 → Storyyard 패킷 내보내기 → 실제 사람 선택 기록을 연결했다. 기존 Book과 A/B레일의 뜻은 바꾸지 않았다.
- 후보별로 필요한 donor 원문만 넣고, 전체 9절 기획서를 반복 생성하지 않는다. 도입 1~4화와 첫 투자 회수의 이야기·사건 비교·회차 목적만 작성한다. 생성자 자기점수 필드를 두지 않았다.
- 원본·발췌·후보·실제 응답·세션·심사·사람이 읽는 Markdown을 연결해, 내용이 바뀐 오래된 결과로 선택을 기록하지 못하게 한다. 이미 완성된 후보는 재사용하고 부분 저장 상태는 새 모델 호출 전에 확인한다.

### Reference Lab

세 작품에서 일곱 실제 사건 구간을 분석했다. 이번 생성에는 복권 자본 사건을 제외한 여섯 구간을 사용했다. 원본 파일 세 개의 SHA와 일곱 발췌의 행·바이트 일치를 검증했다. 전편 분석이나 작중 금융·특허 수치의 현실 정확성 검증은 아니다.

금융형은 《금수저 투자백서》의 파운드 진입과 다음 영국 자산 연결을, 사업형은 《연봉 1조 신입사원》의 묻힌 기술 → 시제품 → 매각 → 자기 몫 연결을 사용한다. 《독식하는 재벌 3세》 1~4화가 주축이다. 금수저 8~11화와 실제 청산 완료 이후는 이번 독해 범위에 포함되지 않는다.

### Storyyard

기존 검토 화면에서 구간 변주 두 안의 전문과 독립 심사 근거를 읽을 수 있게 했다. 새 v5 패킷의 판정 의미는 변주 방향 선택이다. 기존 v1~v4를 바꾸지 않고 별도로 수용한다. 선택·보류·반려의 이유를 후보에 연결해 기록하며, 다른 변주 후보로 이동할 때 이전 후보의 이유가 잘못 넘어가지 않도록 했다.

실제 API 저장 함수는 모의 DB에서 후보·패킷 SHA, 올바른 v5 판정, pending 상태와 응답 의미를 확인했다. 본문 적용용 API로 변주 선택을 처리하지 않는다. 이번 실행은 로컬 패킷 준비까지이며, 배포된 Storyyard의 실제 화면·DB에 반영됐다는 뜻은 아니다.

## 이번 구현의 경계

현재 실행 경로는 InkOS 네이티브 CLI와 로컬 Storyyard 패킷이다. 새 변주 명령의 Hermes 자동 배차, Storyyard 판정의 자동 회수·종료, 선택 이후 전체 기획 확장까지 자동으로 연결한 것은 아니다. 전체 기획서·작품·A/B레일·원고 생성도 아직 실행하지 않았다.

스키마와 명시적 자기평가 탐지는 구조·입력 오염을 검사한다. 모든 은근한 자기칭찬, 상업적 재미, 원문 이해를 기계적으로 증명하지는 않는다. 실제 원문 심사와 사람의 비교 판단을 계속 사용한다.

모델 설정과 기존 p01 카나리는 보존 대상이다. 기존 dirty 작업을 유지했으며 커밋·푸시·원격 배포를 하지 않았다.
