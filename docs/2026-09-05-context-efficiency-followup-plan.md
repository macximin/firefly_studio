# Firefly 컨텍스트 효율 후속 작업 계획

작성일: 2026-09-05. 사용자 요청: “후속 작업 리스트업 이후 계획 후 처리 요청. goal”.

## 목표와 우선순위

기존 원문·복원 근거를 충실하게 읽고 기획서까지 만드는 공정에서 불필요한 재생성과 코딩 지침 비용을 줄인다. 주인공 자신의 이득·목표 우선, 원작 상업 엔진, 단기·장기 목적, WHO/WHAT/HOW/WHERE/WHEN/WHY와 기획서 9개 항목은 그대로 판단한다. 토큰 감소 때문에 이 기준을 약화시키지 않는다.

직전 완료 기록은 `2026-09-05-astra-migration-context-efficiency.md`다. 당시 효율 개선안은 미구현이었다. 이번 작업에서 목록·계획·구현·검증 결과를 연결한다.

| 순서 | 후속 작업 | 구현 범위 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | 호출별 사용량과 실패 기록 | InkOS Codex adapter와 요청별 실행 문맥 | 실제 raw usage·stage·모델·지침/입력 SHA·시각 보존, 실패도 기록, 미제공 값은 null |
| 2 | 형식 오류로 인한 전체 후보 재생성 제거 | pitch 생성과 제한된 JSON 수정기 | 수정 전 값·원본 SHA·허용 경로 결속, 변경 외 내용 보존, 전체 계약 재검증 |
| 3 | 사실 교정의 입력 범위 축소 | 원문 사실과 모든 지정 출현부 결속, prepare/run/apply CLI | 원문·원본 해시 검증, 모든 출현부에 수정/유지 판정, 새 slate 생성, 새 독립심사 필요 |

캐시 적중은 입력 정렬만으로 보장하지 않는다. 캐시 breakpoint API를 지원하지 않는 CLI에 임의 설정을 추가하지 않는다. 먼저 raw cache/read/reasoning 기록을 복구해 실측한다.

## 구현 설계

### 호출 기록과 지침 파일

기존 Pi Usage와 과거 transcript를 유지하고 호출별 별도 증거를 남긴다. raw usage event는 손실 없이 기록하고, 입력·출력·캐시·reasoning 정규화 값은 별도로 둔다. 캐시는 입력, reasoning은 제공되는 경우 출력의 일부로 해석하며 두 번 더하지 않는다. 제공되지 않은 값과 실제 0을 구분한다. 중단된 실행은 시작 기록과 완료 기록의 차이로 식별한다.

stage/session/request/candidate 정보는 호출별 문맥에 넣는다. 캐시되는 모델 객체에 stage를 보관하지 않아 생성→교정 또는 동시 실행 간 잘못된 라벨 전이를 피한다. 기본 계측 파일에는 사적 원문이나 인증값을 저장하지 않고 입력 크기·해시를 남긴다.

`llm.extra.codexModelInstructions={path,sha256}`를 선택적으로 지원한다. 시작 전에 UTF-8·내용·해시를 확인하고 같은 bytes를 임시 실행 폴더에 복사한다. 생략하면 기존 기본 지침을 쓴다. 원문, 역할/스킬 지침, 사용자 요구와 명시 도구 명세를 직렬화하는 InkOS 입력은 바꾸지 않는다. 최종 기본값 적용은 실제 비교 결과를 보고 결정한다.

### 형식 교정

오류 위치를 문자열에서 추측하지 않고 구조화된 경로로 보존한다. 원본 SHA, 오류 경로, 변경 전 값, 허용 경로, 필요한 관련 값만으로 교정 요청을 만든다. 변경은 복제본에 적용하고 전체 후보·source binding을 재검증한다. 배열 삽입·삭제·재정렬, 전체 객체 교체, prototype 경로, 중복/중첩 경로와 근거 없는 원작 사실·좌표 변경은 허용하지 않는다.

정확한 숫자 형식 변환이나 이미 유효한 점수의 합계처럼 의미 보존을 프로그램이 증명할 수 있는 경우에는 모델을 다시 부르지 않고 처리한다. 의미를 새로 써야 하는 누락, 파싱 실패, 위치가 불분명한 오류는 전체 후보를 자동으로 다시 생성하지 않는다. 원본 응답과 진단을 보존하여 원인을 확인할 수 있게 한다. 실제 생성 카나리에서 이런 실패가 발생하면 원인을 수정하고 다시 검증한다.

### 사실 교정

원본 전체 후보 SHA에 결속한 사실·출현부 목록을 입력으로 삼는다. 각 출현부는 원작 사실 진술, 후보의 의도된 유지, 후보의 의도된 변주를 구분한다. 모델이 의미상 모든 언급을 빠짐없이 찾았다고 자동 주장하지 않는다. 요청에 지정된 출현부는 모두 한 번씩 수정 또는 근거 있는 유지로 처리한다.

원문 근거는 해시와 정확 범위로 검증한다. 사실 교정 호출에는 해당 원문과 연관 출현부를 보내며, 임의 요약으로 근거를 대체하지 않는다. 적용은 원본을 덮지 않고 새 비정사 slate를 만든다. 이전 심사·사람 선택은 새 slate로 복사하지 않는다. 이전 검토 결과는 이전 원본에 관한 기록으로 남고, 새 후보는 전체 후보·기획서·동일 원문을 보는 독립심사를 거친다.

### 역할과 도구

새 스토리 계층이나 새 Storyyard 계약을 만들지 않는다. 기존 `pitch-review` 세션에 적합한 짧은 심사 지침을 제공하고, 교정은 별도 세션과 명시적 무도구 옵션으로 실행한다. 이 옵션은 세션 캐시 재사용 판단에도 포함한다. `suppressProductionTools`가 읽기·리서치 도구를 남긴다는 점과 구별한다.

## 검증 순서

1. 변경 전 config·dirty file SHA와 기존 카나리 입력/출력 해시를 기록한다. 기존 변경을 덮거나 커밋하지 않는다.
2. 각 모듈의 정상·변조·stale·누락·실패 경로를 검증하고 Core/CLI를 빌드한다. 적용된 변경이 있는 범위만 회귀한다.
3. 같은 Astra/high·binary·catalog·입력으로 기본 지침과 최소 지침을 제한된 실제 호출로 비교한다. 정답이 고정된 입력으로 형식·사실 보존과 계측을 먼저 확인한다.
4. 실제 원문에 근거한 기획 또는 교정 카나리로 전체 계약과 원문 충실성을 확인한다. 독립 심사는 전체 결과와 동일한 전체 reference bundle을 받는다. 사실 교정에 사용한 정확한 원문 구절이 이 묶음에도 포함되는지 확인한다. 새 후보를 정사나 사람 선택으로 승격하지 않는다.
5. 입력/출력/캐시/reasoning, 재시도 수, 바뀐 필드 수, 독립심사 결함을 함께 기록한다. 작은 표본의 절감률을 전체 작품 공정의 보장으로 표현하지 않는다.
6. 결과가 확인된 설정만 현행 프로젝트에 적용하고, 미채택·추가 검증 필요 항목을 결과 문서에 명시한다.

## 변경 소유와 작업 경계

- HQ: 이 계획과 결과·검증 증거, 실행 설정, 통합과 카나리.
- InkOS: 모델 호출·계측, 기획 생성/교정·심사 코드와 CLI.
- Reference Lab: 기존 원문·복원 자료를 읽기 입력으로 사용한다.
- Storyyard: 기존 projection/receipt 형식을 유지한다.

이번 goal에는 로컬 코드·설정·비정사 검증 실행이 포함된다. 기존 작품·기획서·사람 결정과 원문은 별도 새 결과로 보존한다. 배포, 커밋·푸시, 자동화 활성화, 정사 승격, 원고 출고는 이 작업에 포함하지 않는다.
