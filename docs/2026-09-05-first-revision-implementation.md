- InkOS: 기존 `pitch slate`에 원작 우선 실행을 추가했다. 원작의 자기 목표·선택·실행·자기 몫을 복원한 뒤 지정한 표면과 국소 인과만 바꾼다. 주축 하나로 실행하며 없는 보조 작품·새 Human Premise를 만들지 않는다.
- 심사: 생성에 쓴 원문·복원·팩을 해시 대조 후 동일하게 제공한다. 자기 이익 우선, 원작 보존, 읽는 재미를 별도 판정하며 앞의 두 항목이 실패하면 높은 총점으로 추천할 수 없다.
- 공동 계약: 바깥 HIL v3를 유지하고 원작 근거를 `spineRetention/v2`로 구별했다. 새 후보는 전체 `projectPlan`과 독립 `sourceChecks`를 전달한다. 기존 v1 전제 확장과 과거 후보를 다시 쓰지 않는다.
- Storyyard: 전체 기획서 9절, Markdown 원문, 원작 복원, 선택과 자기 이득의 대조, 실제 보상, 확인 범위, 독립 심사의 근거를 읽는다. 원작 원문 전문은 외부 패킷에 넣지 않는다.
- 용어: 기획의 성과·관계 항목과 실제 A/B레일을 구별한다. 기존 A레일 도착점, B레일 아크, 연결된 1~3화 ArcPacket을 그대로 쓴다. 기존 Storyyard 정본의 아크·블록 대응은 바꾸지 않는다.

선택은 기획 검토 결과로만 남긴다. 원작 binding을 Book에 설치하고 실제 A/B레일과 연결하는 다음 차수가 구현되기 전까지 새 방식의 Book 승격은 지원하지 않는다.

원작에는 가족·그룹 보호와 복수의 동기가 실제로 있다. 이를 지우거나 인정·우정을 얻기 위한 희생으로 바꾸지 않는다. 자기 회사의 돈을 우선 쓰고, 직원 아이디어의 성과보수와 자신의 아이디어 보수를 구별하며, 사장 직함과 전권 위임에 만족하지 않고 지분을 요구하는 선택이 이번 검증의 핵심이다.

## 실제 기획 카나리

초기 실행: `chaebol-source-first-20260905-v1` · 최종 검토 자료: `chaebol-source-first-20260905-v4`. 같은 두 후보의 교정 이력을 구별한 ID다.
모델: Codex transport의 `gpt-5.6-sol`, reasoning `high`. 두 후보는 같은 원문·모델·예정 분량 751화로 실행한다. Astra와의 모델 비교가 아니다. 기존 실패 후보를 덮어쓰지 않는 새 실행이다.

원작 복원 Markdown 19,390바이트와 원문 발췌 168,340바이트에 주축 팩을 추가한다. 앞부분을 잘라 입력하지 않는다. 주인공·기업·현장 외장을 바꾸는 안과, 같은 중심을 유지하면서 인재 영입의 현장·대화 전략까지 국소 변경하는 안을 비교한다.

첫 자동 생성은 두 후보의 전체 기획서를 만들었지만 p02의 후속 기대 항목 형식이 마지막 검사에서 실패해 정식 slate를 저장하지 못했다. 원본 응답과 실패 결과를 보존했다. 생성 예시에 실제 객체 필드를 명시했고, 수혜자 이름 3자를 거절하던 불필요한 최소 길이 조건도 고쳤다.

독립 원문 대조에서는 두 후보 모두 자기 회사·수익·인재·지분의 중심은 유지했다. 그러나 p01의 직접 명의와 실소유 혼동, 유가 하락 시점, p02의 가짜 자금 사용 제한과 입학 선물 중복 합산, 법인 설립 순서, 직원 잔류 순서와 내부 명칭 불일치가 남았다. p02에는 원작에 없는 관계 수단의 도덕적 금지 문구도 생겼다. 이런 결과는 모델 교체 없이 입력·검수 경로를 고친 효과와 함께, 현재 자동 초안에 원문 대조가 여전히 필요함을 보여 준다.

이번 카나리에서는 생성 실패 응답을 성공한 native slate로 기록하지 않는다. 원본 문장을 유지한 형식 복구를 별도 기록하고, 같은 Sol/high가 사실 오류가 있는 문자열만 수리한 새 v2 실행 자료를 만든다. 원래 응답·입력 해시·변경 위치·수리 모델·새 결과를 연결하고, 새 native review/export로 이어간다. 두 차례 Sol 수리에서는 각각 35곳과 7곳을 바꿨다. 그 뒤 p02 기획서 6장에 같은 채용 시점 오류가 한 번 더 남아 감독자가 원문과 대조해 한 문장을 고치고 v4로 따로 저장했다. 이 수리 도구는 이번 카나리의 한정된 실행 보조이며 공식 자동 수정 명령을 새로 만든 것이 아니다. 모델 원안, 모델 수리, 감독자 교정을 각각 영수증에 구별했다.

v2 심사 모델은 p02를 96점·SURVIVE, p01을 94점·HOLD로 평가했다. 그러나 당시 원문 대조에는 남은 모순이 있었고, p02의 예산·결재·권한 설명을 구체성의 장점으로 평가했다. 따라서 이 점수나 “첫 아크 제작 가능”이라는 말을 원작 보존·재미의 검증 결과로 채택하지 않는다.

이 발견을 반영해 심사 지침을 좁게 보강했다. 원문 좌표와 정확한 후보 필드를 짝지어 중복 서술의 모순을 먼저 대조하고, 권한·결재 설명의 양을 상업성의 장점으로 보지 않는다. 판단 대상은 주인공이 자기 목표 때문에 내린 선택과 실제 얻어 쓰는 몫이다. 원작에서 실제 소유권이나 실행 권한을 요구하는 행동은 그대로 인정한다.

최종 v4는 **p01 SURVIVE·추천, p02 HOLD**다. p01은 자기 선택과 실현된 몫을 앞세웠고, p02는 타인의 예산·결재 문제 해소가 주인공의 인재 확보를 가릴 위험을 지적받았다. 생성·수리 내용도 함께 달라졌으므로 이를 심사 프롬프트만의 효과로 분리해 증명한 A/B 실험은 아니다.

직접 대조한 범위에서 지적했던 협상 설명, 법인·채용·수익 순서, 사망 장소 단정 및 같은 사실의 반복 설명에는 남은 실질 모순을 발견하지 못했다. [범위 한정 독립 대조](../edge_repos/inkos/.inkos/source-first-canaries/chaebol-source-first-20260905-v1/final-scoped-source-audit.json)에 남겼다. 심사평 자체에는 법인 설립과 원유 수익 시점을 뭉갠 표현도 남아 있어 심사자의 높은 점수·제작 가능 표현을 사실 검수의 대용으로 쓰지 않는다.

최종 [실제 패킷](../edge_repos/inkos/.inkos/source-first-canaries/chaebol-source-first-20260905-v1/storyyard-packet.json)은 기존 바깥 HIL v3로 내보냈다. 원작 근거는 안쪽 v2이고 전체 기획서와 독립 판단을 포함한다. 실제 Storyyard 컴포넌트에서 두 후보 모두 9절이 표시됐으며 데스크톱 1280px와 모바일 390px에서 본문·표를 확인했다. 문서 전체 가로 넘침은 없었다. 실제 slate → 내보낸 패킷 → 별도 기획서 파일 → 로컬 서버 응답의 Markdown이 각각 바이트 단위로 일치했고 두 계약 검증기를 모두 통과했다. [수신 확인 영수증](../edge_repos/inkos/.inkos/source-first-canaries/chaebol-source-first-20260905-v1/storyyard-local-readback.json)에 기록했다. 로컬 컴포넌트 검증이며 운영 인증·선택 화면 전체를 실행한 결과는 아니다.

## 이번 카나리에서 드러난 후속 개선

1. 같은 사실이 보상 목록·장기 개요·기획서에 여러 번 쓰인다. 국소 수리 때 한 필드만 고치지 않고 해당 사실이 나오는 모든 위치를 모아 정합성을 검사해야 한다. 이번에는 원문·후보 대응을 수동으로 확인했으며 일반적인 자동 사실 일치 검사는 아직 없다.
2. 원문 사실 검수와 상업성 비교를 분리해 먼저 사실 모순을 해결하는 순서가 필요하다. 이번 심사 지침은 그 순서를 명확히 했지만 별도 사실 검수 산출물과 자동 연결은 다음 차수다. 입력 원문을 줬다는 사실만으로 심사 정확도가 보장되지는 않는다.

## 적용 상태와 다음 단계

로컬 구현과 실제 검토 자료 준비까지 완료했다. 운영 Storyyard에는 배포하지 않았고 DB·기존 검토 목록·정본은 바꾸지 않았다. 운영 반영 시에는 새 후보 fixture를 통과한 수신기 revision 적용을 확인한 다음 패킷을 가져와야 한다. 현재 사람 선택·Book·A/B레일 확정·ArcPacket·원고는 없다. 커밋·푸시도 실행하지 않았다.

기존 Arc/Rail 스키마·store·Book 모델·EntryContract·Storyyard 정본 매핑과 Foundry sync의 기준 해시는 유지됐다. 기준에 잡은 42개 파일이 모두 남았고 31개는 동일, 바뀐 11개는 승인된 계획 대상이다. 세 하위 저장소 HEAD와 기존 dirty 경로도 유지됐다. 기준에 모든 파일의 수정 전 내용이 있지는 않아 변경 파일 내부의 과거 편집 전량 보존까지 증명하는 것은 아니다.

전체 검증은 중복 재실행을 제외한 관련 테스트 168개 통과다. 최종 해시와 상태는 [구현 증거](evidence/2026-09-05-first-revision-implementation.json)에 기록한다.
